# Requirements — College Football (CFB) Prediction Model

## Overview

PickLedger publishes automated sports picks generated by a family of prediction
models (NFL, MLB, NBA, WNBA, MLS, Tennis, FIFA, etc.). A College Football
model already exists in `CFBPredictionModel/`, but today it:

- Predicts **team markets only** — moneyline, spread, and total — for **all of
  FBS** (no conference focus).
- Runs in **shadow mode** (`shadow_mode: true`, `promotion_status: "not_qualified"`),
  so its picks are filtered out of every public surface and only recorded to a
  forecast-audit ledger. Walk-forward direction rates sit near coin-flip
  (~0.47–0.54), below the ~52.4% break-even for -110 pricing.
- Has **no player props** of any kind. The repo's `player_props/` framework
  supports only NBA, WNBA, and MLB; the grader (`pickgrader_server.py`) has stat
  extractors only for NBA and MLB; and `market_odds.py` rejects any
  `scope == "player"` pick. There is no football player-stat source or grader.

This feature grows CFB into a **full, publishable multi-market model** — team
spread, totals, and moneyline **plus CFB player props** — that runs alongside
the existing models, trains on historical data with machine learning, and
publishes graded picks to the site through the same `model_cache` and
`player_props` pipelines the other models use. Coverage prioritizes the **SEC
first**, then expands to the rest of FBS.

The existing CFB team model is **evolved in place** (`CFBPredictionModel/`) — not
replaced — and the current model's shortcomings are fixed as part of this work.
**Player props are built as a separate subsystem** inside the existing
`player_props/` framework, kept independent of the team model. The remaining new
work is a **strengthened, properly-trained team model**, a **roster-change
adjustment** so old-season data trains fairly, a **model-variant bake-off** that
picks the best predictor by a formal statistical comparison, and the **promotion
path** that lets qualified CFB picks graduate out of shadow mode onto public
surfaces. Periodic in-season retrains are expected; this feature delivers the
first properly-trained iteration and the machinery to repeat it.

## Definitions

- **Team markets** — moneyline (`h2h`), spread, and total (over/under) on a game.
- **Player props** — over/under lines on an individual player's stat
  (passing yards, rushing yards, receptions, passing TDs, etc.).
- **Shadow mode** — a model whose picks are recorded for audit but hidden from
  all public surfaces (parlays, profit desk, the viewer, filters).
- **Promotion** — the gated transition of a model (or a single market) from
  shadow mode to publishable, based on demonstrated graded performance.
- **SEC** — the Southeastern Conference; the initial coverage priority.
- **FBS** — Football Bowl Subdivision (~130 teams); the eventual full coverage.
- **Market-free originator** — the existing CFB contract that sportsbook lines
  are used only as pricing/grading labels, never as model inputs. This
  contract is preserved.
- **Roster-change adjustment** — a mechanism that down-weights or discounts
  old-season signal that no longer reflects the current roster (graduation, the
  transfer portal, coaching turnover), so training on multiple past seasons does
  not overrate teams whose personnel has churned.
- **Variant bake-off** — training several candidate model configurations
  (different algorithms / feature sets / hyperparameters) and selecting the best
  by a defined, reproducible criterion rather than by hand.
- **Model-selection test** — the formal comparison that decides the bake-off
  winner: a likelihood-ratio test (LRT) between nested candidates where
  applicable, plus a held-out walk-forward metric comparison (and an
  information-criterion tie-break, AIC/BIC) for non-nested candidates.

## Requirements

### Requirement 1 — CFB team picks are published as first-class picks

**User story:** As a PickLedger viewer, I want CFB moneyline, spread, and total
picks to appear on the site alongside the other models' picks, so I can see the
CFB model's actionable calls.

**Acceptance criteria:**
1. WHEN the model runs for a slate date THEN it SHALL emit, per eligible game,
   pick rows for `h2h`, `spread`, and `totals` in the same schema the other team
   models use (`sport/league = "CFB"`, team ids/names, matchup, start time,
   selection, line, odds, probability, edge, expected value, decision, units).
2. WHEN a CFB pick's market price is available from the in-house ESPN source
   (`market_odds.py`, key `CFB → ("football","college-football")`) THEN the model
   SHALL use the real posted price instead of an assumed -110.
3. WHEN a CFB pick has met the promotion gate (Requirement 6) THEN it SHALL be
   written into the CFB `model_cache` bucket AND its top-level alias (`cfb`) with
   `shadow_mode: false` so it renders on public surfaces.
4. WHEN a CFB pick has NOT met the promotion gate THEN it SHALL remain
   `shadow_mode: true`, be excluded from all public surfaces, and be recorded to
   the forecast-audit ledger — preserving current behavior for un-promoted
   markets.
5. The model SHALL preserve the market-free-originator contract: sportsbook
   lines remain grading/pricing labels and never enter the feature vector.

### Requirement 2 — CFB player props are generated

**User story:** As a PickLedger viewer, I want CFB player-prop picks (e.g. a QB's
passing yards over/under), so the CFB model covers props like the NBA/MLB models.

**Acceptance criteria:**
1. WHEN the player-props payload is generated for a slate date THEN it SHALL
   include a `CFB` model bucket produced through the existing `player_props/`
   framework (`generator.generate_payload`), not a separate fork.
2. The CFB prop generator SHALL emit picks via `player_props.schema.build_pick`
   with `scope = "player"`, `sport = "CFB"`, a valid `stat_key`/`stat_label`,
   `line`, `projection`, `probability`, `edge`, `decision`, and `units`, matching
   the canonical prop schema.
3. The system SHALL support, at minimum, these CFB prop stat families: passing
   yards, rushing yards, receiving yards, receptions, passing touchdowns, and
   rushing+receiving yards. Each prop's `stat_key` SHALL map to a registered
   market family.
4. WHEN a CFB player's projection and a posted prop line are both available THEN
   the prop SHALL be priced and decisioned (BET / LEAN / PASS) using the same
   thresholds the framework applies to other sports.
5. The CFB prop model SHALL rank and cap published props per slate using the
   framework's existing selection logic (top-N, max-per-player).

### Requirement 3 — SEC-first, FBS-later coverage

**User story:** As the model owner, I want CFB coverage to start with the SEC and
then expand to the rest of FBS, so I can validate quality on a focused set before
going wide.

**Acceptance criteria:**
1. The model SHALL support a coverage scope that can be set to **SEC-only** or
   **full FBS**, controlling which games' picks are eligible for publication.
2. WHEN coverage is SEC-only THEN only games where at least one team is an SEC
   member SHALL be eligible for published picks; other FBS games MAY still be
   modeled in shadow mode for audit.
3. SEC team membership SHALL be resolved from committed data (a conference map),
   not hard-coded in scattered call sites, so it can be updated when membership
   changes.
4. Expanding coverage to additional conferences or full FBS SHALL require only a
   configuration/data change, not new model code.

### Requirement 4 — Historical data is loaded and models are trained with ML

**User story:** As the model owner, I want the CFB model trained on historical
college-football data with machine learning, so its projections are grounded in
past performance rather than hand-tuned heuristics.

**Acceptance criteria:**
1. The system SHALL load historical CFB game data (final scores, closing spread /
   total / moneyline, venue, rest, conference) from a committed, cacheable
   source, following the repo's freshness pattern (TTL + sidecar stamp, cached
   fallback on download failure).
2. The system SHALL load historical CFB player game logs sufficient to train
   player-prop projections for the stat families in Requirement 2.3.
3. Team-market training SHALL use a walk-forward-by-season protocol with strict
   as-of feature construction (no lookahead): each game's features use only data
   from strictly earlier games.
4. The trainer SHALL refuse to train on an insufficient sample and SHALL emit
   walk-forward evaluation metrics (Brier score / direction rates for team
   markets; hit rate / calibration for props) into a metadata artifact.
5. Trained artifacts (models, calibrators, metadata) SHALL be written to the
   model's `artifacts/` directory and the player-props `artifacts/` directory,
   and SHALL be loadable by the serving path without retraining.
6. The team feature set SHALL be strengthened beyond the current 16 form/Elo/rest
   features by adding at least: opponent-adjusted offensive and defensive
   efficiency, pace/possessions, and a home/travel factor. (Injuries, weather,
   and transfer-portal features are out of scope for this feature and noted as
   future work.)
7. Training SHALL apply a **roster-change adjustment** so that old-season data
   trains fairly: signal from prior seasons SHALL be discounted relative to the
   current roster (e.g. season-recency weighting plus a per-team continuity
   factor derived from returning production / roster carryover), and the chosen
   adjustment SHALL be recorded in the metadata artifact.

### Requirement 5 — Best model is chosen by a variant bake-off with a formal test

**User story:** As the model owner, I want the trainer to try several model
variants and pick the best predictor using a real statistical test, so the
shipped model is the strongest available and not a hand-picked guess.

**Acceptance criteria:**
1. Training SHALL fit **multiple candidate variants** per target — spanning at
   least two algorithm families (e.g. regularized linear vs. gradient-boosted
   trees) and alternative feature sets — under the identical walk-forward split.
2. The trainer SHALL select the winner by a **defined, reproducible criterion**:
   a likelihood-ratio test (LRT) between nested candidates where the comparison
   is nested, and a held-out walk-forward metric comparison with an AIC/BIC
   tie-break for non-nested candidates.
3. The comparison SHALL use the same held-out walk-forward folds for every
   variant so results are directly comparable, and SHALL avoid selecting on
   in-sample fit.
4. The metadata artifact SHALL record every variant tried, its walk-forward
   metrics, the test statistic(s) and p-value(s) or information criteria, and
   which variant was selected and why.
5. Only the selected variant's fitted artifacts SHALL be shipped for serving;
   losing variants SHALL NOT be published but their metrics SHALL remain in
   metadata for auditability.
6. Re-running training on the same data and seed SHALL reproduce the same variant
   selection.

### Requirement 6 — CFB picks are automatically graded

**User story:** As a PickLedger viewer, I want CFB picks graded to win/loss/push
automatically, so the ledger and rankings reflect real outcomes.

**Acceptance criteria:**
1. WHEN a completed CFB game is available on the ESPN college-football scoreboard
   THEN the auto-grader SHALL grade the game's team picks to win / loss / push
   using the existing `SPORT_TO_ESPNSLUG["CFB"]` path.
2. WHEN a CFB player prop's game has completed THEN the grader SHALL extract the
   player's actual stat from the ESPN football box score / summary endpoint and
   grade the prop to win / loss / push. (This requires a new football player-stat
   extractor; without it, CFB props would remain ungradable.)
3. Grading SHALL treat an exact line match as a push and otherwise decide by
   direction, consistent with the other sports.
4. WHEN a CFB game is canceled or postponed THEN its picks SHALL be graded as a
   push.
5. Committed grades and start times SHALL be preserved across cache refreshes,
   per the existing merge contract.

### Requirement 7 — Publishable quality is gated by demonstrated performance

**User story:** As the model owner, I want CFB picks to go public only after they
demonstrate a real edge, so the site never publishes coin-flip picks.

**Acceptance criteria:**
1. The system SHALL define an explicit, documented promotion gate per market
   (team spread, team total, team moneyline, and player props) based on graded
   sample size and measured performance (e.g. minimum graded picks and a
   direction/hit rate clearing the break-even threshold for the prevailing
   price).
2. WHEN a market's graded performance meets its gate THEN that market's picks
   SHALL become publishable (`shadow_mode: false`) while markets that have not
   met the gate remain in shadow mode.
3. The gate evaluation SHALL run from committed graded history, not mutable live
   cache, so promotion status is reproducible.
4. The model's metadata artifact SHALL record each market's current
   `promotion_status` and the metrics behind it.

### Requirement 8 — Automated, scheduled operation

**User story:** As the model owner, I want CFB to train and refresh on a schedule
like the other models, so picks stay current without manual runs.

**Acceptance criteria:**
1. The daily model-cache refresh SHALL invoke the CFB team model so its bucket is
   regenerated each slate day, wired into the same refresh registry the other
   models use.
2. The player-props refresh SHALL invoke the CFB prop generator so a CFB prop
   bucket is produced each slate day.
3. A scheduled or dispatchable training workflow SHALL retrain the CFB team and
   prop models and publish updated artifacts, mirroring the existing per-model
   training workflows.
4. The site up-check / freshness guard SHALL include CFB in its required-model
   checks once CFB is promoted, so a missing CFB refresh is detected.

### Requirement 9 — Integration is complete and non-breaking

**User story:** As a maintainer, I want the CFB model wired into every place the
other models are registered, so nothing silently drops CFB picks.

**Acceptance criteria:**
1. CFB SHALL be registered in every integration point the other team models use:
   the model runner/registry, `market_odds.py` sport + bucket keys, the odds-API
   sport key, the grader's league slug, deployed/team-prop model key lists, and
   the site up-check required-model list.
2. The frontend SHALL render CFB picks with correct labels and filters
   (`data.ts` CFB market labels; `main.ts` primary filters and league mapping).
3. New behavior SHALL be covered by smoke tests mirroring the existing per-model
   tests, including: pick-schema conformance, no-lookahead in feature
   construction, decision thresholds, artifact-metadata contract, promotion-gate
   logic, prop-schema conformance, and grading of a completed CFB game and prop.
4. Existing models' behavior SHALL be unchanged; the full existing smoke suite
   SHALL continue to pass.

## Out of scope

- Injury reports, weather, and transfer-portal features (future enhancement;
  the feature set is strengthened but these specific signals are deferred).
- In-game / live prop markets and alternate lines.
- FCS coverage and FCS-vs-FBS games as publishable picks.
- Multi-book line shopping beyond the in-house ESPN source plus the optional
  Odds API sharp-price enrichment already present in the repo.

## Resolved decisions

- **Code location:** Evolve the existing `CFBPredictionModel/` in place (build on
  top of it), not a fresh `CFBv2PredictionModel/`.
- **Player props:** Built as a separate subsystem inside the existing
  `player_props/` framework, independent of the team model.
- **Coverage:** SEC-first for publishable picks; the rest of FBS is modeled in
  shadow mode and becomes publishable as coverage expands (config/data change).
- **Model selection:** The shipped variant is chosen by a formal test — LRT for
  nested candidates, walk-forward metric comparison with AIC/BIC tie-break
  otherwise — not by hand.
- **Retrain cadence:** Periodic in-season retrains are expected; this feature
  delivers the first properly-trained iteration plus the machinery to repeat it.
